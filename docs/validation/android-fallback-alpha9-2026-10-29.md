# Android native connection fallback — Alpha.9

CHG-20261029-ANDROID-FALLBACK. User authorized a new Android-only compatibility Alpha, preserving configuration and healthy devices, with bounded diagnostics and backend TLS correlation.

Published candidate: 1.1.2-alpha.9. Build baseline is the fixed, previously published Alpha.7 source snapshot, with only this change overlaid; unrelated unpublished Alpha.8 work is excluded. Stable metadata and existing assets are retained. The immutable local source/build receipts are under the ignored output/wujie-sync-1.1.2-alpha.9 directory. Mainline version metadata remains 1.1.1; Alpha version metadata is set only in the fixed build snapshot.

The primary fetch path remains first. Only Android network exceptions attempt requestUrl after a signed, same-authority, credential-free identity check. HTTP errors, failed identity checks and parent cancellation do not select fallback. A failed POST/PUT/DELETE is not automatically resent in that invocation; a later normal recovery attempt can use the selected transport. Selection is memory-only. Other hosts and healthy Android retain the original transport.

Diagnostics retain at most100 local stage/runtime entries, rate-limited per stage, and enqueue compatible opaque events in the existing outbox. The selected-event UUID correlates with a random probe header, attached to at most20 native requests per selection. Nginx records TLS/cipher/HTTP/status/elapsed time and bounded encoded version metadata for tagged requests only. Client version metadata contains Obsidian/Alpha versions and a Chromium version extracted from the host browser version string; it is not an exact Android System WebView package-version query. No credentials, note body or file names are logged. Fully offline events cannot reach the backend until connectivity returns; local export remains possible.

Validation: Windows final runtime suite288 total,287 passed,1 skipped,0 failed. WSL runtime suite285 total,283 passed,2 skipped,0 failed, followed by the final17 Android transport/diagnostic cases all passing. The latter include ciphertext/body/source-mtime roundtrip, cancellation/late responses, maximum4 outstanding native operations, authority validation, credential-free selection, no failed-write replay, healthy/non-Android isolation, diagnostic retention and notebook binding. Both regional builds and dependency checks passed. Community lint passed with0 errors and6 warnings; an initial missing-tool dependency, coverage-count failure and navigator-version lint errors were retained and corrected before acceptance. Host version metadata does not determine platform selection; Platform.isAndroidApp does.

Hub parser/three-file digests/tamper rejection passed.15 public user-domain files were anonymously downloaded and matched SHA256 after publication. Stable records and history were verified unchanged. A concurrent metadata update prevented the first publication attempt before mutation; the latest metadata was reread and merged before the successful attempt. No synchronization application restart or user-vault installation occurred. Only the tagged Nginx diagnostic log configuration was added and reloaded, with config/health checks and a synthetic TLS1.3 probe receipt.

Platform boundary: Windows, macOS, desktop Linux, iPhone/iOS and iPad/iPadOS do not enable this adapter; physical acceptance is unperformed. Android functionality is synthetic-validated, but the affected Android13/Obsidian1.14.4 tablet still needs native connectivity and full synchronization acceptance. Browser Edge success does not establish requestUrl reachability. Lifecycle/background/lock-screen and network-change behavior need physical testing. No UI/touch/layout change or settings migration is introduced. Code-only rollback preserves data.json, keys and progress.

Limitations: requestUrl buffers responses and exposes no underlying abort or redirect-policy controls. Completed replies are capped at8MiB, with four operation slots retained until underlying settlement; late results after cancellation are ignored. Visible redirects/foreign final URLs are rejected, but hidden host-followed redirects are not thereby equivalent to fetch redirect:error. Calls are restricted to the configured HTTPS authority's /ss2/ API. Physical native-host behavior remains an Alpha acceptance boundary. Client JavaScript does not report negotiated TLS; handshake failures have no negotiated protocol to record.
